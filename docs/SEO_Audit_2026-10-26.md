## 2. Schema markup — what's missing and what to change

### 2.1 Directory profile pages (HIGH — commercial core)
`src/app/[locale]/directory/[slug]/page.tsx` has **zero** `generateMetadata` and **zero** JSON-LD. Live evidence: `/en/directory/al-mutalib-perfumes` served the generic site title — the same title the 404 page uses — with no canonical and no OG tags.
**Fix:** add `generateMetadata` via the existing `buildMetadata` (title from the business name, canonical `/en/directory/<slug>`), and emit the already-written `businessSchema` Organization block (pass `business:` for the first time — it's dead code today). **Do not** put phone/email/address in it — the contact-projection policy strips those from the page and the schema must not leak them (the `jsonld.ts` header comment says exactly this).

### 2.2 Home page (HIGH)
No `WebSite`, no `SearchAction`, no `Organization` anywhere in the site.
**Fix:** add to the root layout or home page:
- `WebSite` with `name: "OudGuide"`, `potentialAction: SearchAction` targeting `/en/directory?search={search_term}` (the hero search already routes there).
- Global `Organization` node with `url` + logo (`/logo.png` serves 200).

### 2.3 Article schema correctness bugs (MEDIUM)
In `src/lib/jsonld.ts`:
- `author: {'@type':'Organization', name: article.reviewer}` → resolves to `"OudGuide editorial review"`, which is a descriptor, not an entity. Make author/publisher the `Organization "OudGuide"` with `url`; keep the reviewer string as page-visible-only, or surface a real named reviewer (see §5) as `Person`.
- `headline` uses `title.slice(0, 110)` — cuts mid-word with no ellipsis (metadata.ts trims properly at 62/157; the schema path doesn't).
- `BreadcrumbList` item URLs are built as `${siteUrl}${crumb.href}` with **no guard** that the href carries the locale prefix — safe for all five current call sites (verified), latent 404 for the next one.
- `inLanguage` is re-derived from the path instead of the locale the call site already knows.
- Add `mainEntityOfPage` and publisher `url`/`logo` (no per-article image field exists; OG uses the shared image).

### 2.4 Wrong / missing types (MEDIUM)
| Surface | Today | Should be |
|---|---|---|
| Glossary terms (`glossary/[slug]`) | `Article` | `DefinedTerm` (`name`, `description` from `directAnswer`, `inDefinedTermSet` → glossary hub URL) |
| Hub indexes (guides/products/glossary) | `Article` only | add `ItemList` from `hubChildren()` (child.href + child.label already exist) |
| Directory profile FAQ accordion | none | `FAQPage` (4 hard Q&As incl. MOQ — perfect material); only profile FAQs qualify, not RFQ/membership copy |

### 2.5 hreflang (HIGH bug on roots, otherwise sound)
`buildMetadata` passes `alternateLocalePath` on 30 of 31 call sites — good. **But on the bare-root alternates it self-mismatches:** live `/en` emits
`rel="alternate" hreflang="en" href="…/ar"` **and** `hreflang="ar" href="…/ar"` — both entries point at the Arabic home (confirmed in live HTML; the EN-home self-entry is `languages[locale]` correctly set, then the sibling-derivation branch overwrites `en` because `alt = "/ar"` doesn't start with `/ar/`). The AR home is symmetric.
**Fix:** in `metadata.ts`, normalize bare-root alternates (`/ar` ↔ `/en`) before the starts-with logic; ~5-line change, one file.
Note: because the Arabic tree is noindexed, pointing hreflang at it is currently *valid* (alternates may be non-indexable) — but `x-default` is absent; add `x-default → /en` when the Arabic gate is lifted.

## 3. Internal linking — what's missing

Verified against the data files, not just the agent's claims:

### 3.1 Orphan clusters (HIGH)
- **36 destination guides** (`buying/in/*`): no hub children list references `buying/in/` at all (confirmed: `hubs.ts` buying hub lists only 4 frameworks), and the /guides index "orphans" filter excludes them because their parent is `buying`. Reachable only via sitemap/URL.
- **40 of 41 origin regions** and **13 origin-country pages**: zero inbound refs outside their own definition files.
- **4 of 5 comparisons**: only `comparisons/india-and-cambodia-oud` appears in a hub children list (`hubs.ts:490`); the other 4 are orphans.
- **`/shortlist`**: exactly one inbound link on the whole site (a button on the directory index).

**Fix (data-only, all flow through `articlePath()` so locale-correctness is automatic):**
1. `hubs.ts` buying hub: add the 36 `buying/in/*` slugs as children (`hubChildren` auto-drops unreviewed).
2. `hubs.ts` comparisons hub: add the 4 missing slugs.
3. `hubs.ts` origins hub: add the 13 country slugs; then add each country's regions to that country's `related` array in `origin-countries.ts` / `origin-regions.ts` so region pages cross-reference.
4. Add `/shortlist` to the Footer "For Distillers & Buyers" column.

### 3.2 Trap-door territory pages (HIGH — one-function fix)
203/249 `world/[iso2]` pages render an empty "Related Market Briefs" block. Root cause: `publishedLabel()` (`route-resolver.ts:399`) looks up the manifest record at the *resolved* path, but territory aliases resolve to `/en/world/AF` while the manifest record lives at `/en/world/afghanistan/` — label is null, link silently dropped. India shows links only because it has ~21 editorial routes, not because the code works.
**Fix:** in `publishedLabel`, look up the manifest by the *candidate* (pre-redirect) path, falling back to resolved. One function, populates 203 pages.
Also: territory pages never link to the matching destination guide (`/guides/buying/in/<country>`), origin guide, or the published directory filter shapes (`/directory/wholesalers/by-origin/<slug>`, `…/serving/<slug>`). Add a deterministic outbound block using the country registry (`countrySlugForCode`), each target run through `resolvePublishedPath`.

### 3.3 Directory profile pages are link SINKS (MEDIUM)
`directory/[slug]/page.tsx` renders `product_families` and `handles_origins` as inert chips even though `/products/<family>` and `/directory/wholesalers/by-origin/<origin>` are published shapes. Linkify the chips (resolve via `getArticle("products/…")` / `resolvePublishedPath`) + a small "Learn more" strip into glossary/products.

### 3.4 Other links worth adding (LOW–MEDIUM)
- Article `nextSteps` are plain text that name specific pages ("Read the India and Cambodia comparison") — readers can't click. Optional: a resolver-based slug-mention pass; the hub/related fixes above cover most of it.
- Glossary terms in guide bodies are not inlined as links (bodies are plain strings; cross-linking happens only via `related`). Cheaper alternative: add prominent "Key terms on this page" chips per article from its text.
- Chrome deep-links (Footer/Header: cites-regulations, copper-deg, wild-vs-cultivated) all ride 301 alias redirects. Keep the redirects for search traffic, but point first-party links at the canonical slugs to save a hop.

### 3.5 Missing test infrastructure
- No **orphan/reachability test** (every reviewed article path has ≥1 inbound link). `publishedLinkTargets()` (`route-resolver.ts:475`) was written "for the link-crawler test" that was never built — zero callers. A `node:test` building the inbound set from `related` + hub `children` + chrome link lists would have caught §3.1–3.3 directly and enforces the "link only to published targets" rule going forward.

## 4. Topical authority — coverage map and the 10 gap pages

The pillar structure is strong; the gaps are in high-commercial, high-intent oud queries with near-zero coverage (grep: "fraud"/"freshness"/"moisture" together get <10 corpus hits):

1. **Fraud & counterfeit identification guide** — `/en/guides/quality/fraud-identification` · "how to tell if oud is real" · the site's trust model ("what a badge does not mean") makes this its natural flagship.
2. **Oud oil vs attar** — `/en/guides/fragrance/oud-oil-vs-attar` · buying/choosing-oud-oil exists but the comparison query is open; IFRA + concentration-label data is already sourced.
3. **Freshness & moisture testing** — `/en/guides/quality/freshness-testing` · top practical buyer question.
4. **CITES import by market (US/UAE/EU)** — `/en/guides/trade/cites-import-by-market` · 79 CITES mentions scattered across 35 destination guides with no doc hub.
5. **Reading an oud lab / GC-MS report (worked example)** — extends the existing lab-report-reading page.
6. **Price-per-gram framework** — `/en/guides/buying/oud-oil-price-framework` · "oud oil price per gram".
7. **Attar quality evaluation** — attar has zero dedicated quality page.
8. **Oud in the fine-fragrance market** — fragrance pillar is thin (5 guides); IFRA standards already in the registry.
9. **Aquilaria species guide** — POWO + ITTO species sources in the registry; species pages beat country pages for "agarwood species".
10. **Gulf grade-label hub** — promote the existing grade-ladder content into a hub with the 9 label pages as children (21 slugs already exist; cheap win, and it's the seed of original asset #1 below).

- **Update the stale "twenty-five-source registry" line** in the editorial-policy copy — the registry is 17.
- Rotate freshness dates as pages are genuinely re-reviewed (the badge renders `reviewedOn` directly; no code change).
- Add the funding line to About ("funded by supplier membership, AED 1,200/yr, which never affects ranking or verification — see ownership").

## 6. Original data / research

**Inventory — what exists:** the 17-source registry (with per-source scope), the 772-route manifest, the directory register with per-field verification states, the 9-label Gulf catalogue, and the **documented AlMutalib retail-catalogue audit** (`docs/ALMUTALIB_TAXONOMY_DELTA.csv`, 2026-10-21 — currently only referenced inside a `reviewMethod` string, not published or in the registry).

**Missing: everything measured.** Zero first-party price/moisture/yield data, zero surveys, zero time-series. The site is the best *citation* source on oud; it owns no dataset.

**Three buildable assets (in priority order):**
1. **Publish the grade-label dataset** (~2–3 days, data already audited). Turn the AlMutalib audit into a public, dated, citable page: 9 labels × 2 catalogues, spellings, positions, "no published threshold", with the honest "what this does not establish" framing the site already uses. Becomes the canonical link magnet for "oud grades / VIP / Seufi" queries and gets the Article schema with cited methodology.
2. **CITES import documentation matrix, by market** (~1 week). US/UAE/EU requirement matrix (schedule, permit needs, CITES cert vs ITTO/TRAFFIC guidance) built *strictly* from the appendices + TRAFFIC/ITTO sources already in the registry, each cell citing its source's scope. High commercial value, fully evidence-based; publishes as gap page #4.
3. **Oud price & market observation index** (2–4 weeks, **needs your decision**). Track anonymized price-per-gram/moisture observations captured through the existing RFQ flow ("OudGuide price observations, n=X, collected Y"). This is the only way to own "how much does oud cost" queries. Must stay labelled OudGuide-collected observations, not market truth.
